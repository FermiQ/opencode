# db.go

## Overview

The `db.go` file, located in the `internal/db` package, is **auto-generated by sqlc**, a command-line tool that generates type-safe Go code from SQL queries. This file should **not** be manually edited as changes will be overwritten by subsequent `sqlc generate` runs.

It provides the Go bindings and types necessary to interact with the database based on the SQL queries defined in the `sql/` directory (e.g., `files.sql`, `messages.sql`, `sessions.sql`). It defines an interface `DBTX` for database operations (supporting both `*sql.DB` and `*sql.Tx`), a `Queries` struct that groups database query methods, and constructor functions for this struct.

## Key Components

### Interfaces
- `DBTX`: An interface that abstracts database operations like `ExecContext`, `PrepareContext`, `QueryContext`, and `QueryRowContext`. This allows the generated query methods to work with both standard database connections (`*sql.DB`) and transactions (`*sql.Tx`).

### Structs
- `Queries`: A struct that holds a `DBTX` interface (either a `*sql.DB` or `*sql.Tx`) and prepared statements (`*sql.Stmt`) for all the SQL queries defined in the `.sql` files processed by `sqlc`. Each field corresponding to a prepared statement is named after the query (e.g., `createFileStmt`, `getMessageStmt`).

### Functions
- `New(db DBTX) *Queries`: A constructor function that returns a new `Queries` struct initialized with the provided `DBTX` (typically a `*sql.DB` connection pool). This version does not pre-prepare statements.
- `Prepare(ctx context.Context, db DBTX) (*Queries, error)`: A constructor function that returns a new `Queries` struct and also prepares all defined SQL statements against the provided `DBTX`. This is generally more performant for repeated queries.
- `(q *Queries) Close() error`: Closes all prepared statements held by the `Queries` struct. It's important to call this when the `Queries` object is no longer needed, especially if `Prepare` was used.
- `(q *Queries) exec(ctx context.Context, stmt *sql.Stmt, query string, args ...interface{}) (sql.Result, error)`: An unexported helper method for executing queries that don't return rows (e.g., INSERT, UPDATE, DELETE). It uses a prepared statement if available and handles transactional contexts.
- `(q *Queries) query(ctx context.Context, stmt *sql.Stmt, query string, args ...interface{}) (*sql.Rows, error)`: An unexported helper method for executing queries that return multiple rows. It uses a prepared statement if available and handles transactional contexts.
- `(q *Queries) queryRow(ctx context.Context, stmt *sql.Stmt, query string, args ...interface{}) *sql.Row`: An unexported helper method for executing queries that return a single row. It uses a prepared statement if available and handles transactional contexts.
- `(q *Queries) WithTx(tx *sql.Tx) *Queries`: Returns a new `Queries` struct that is associated with the provided SQL transaction `tx`. This allows multiple database operations to be performed atomically within a single transaction, using the same prepared statements from the original `Queries` object.

**Note:** This file also contains numerous exported methods on the `*Queries` struct, one for each SQL query defined in the `*.sql` files (e.g., `CreateFile`, `GetMessageByID`, `ListSessions`). These methods are generated by `sqlc` and are not listed individually here due to their large number. They typically take a `context.Context` and query-specific parameters, and return data and/or an error. The actual SQL for these methods is found in files like `files.sql.go`, `messages.sql.go`, etc., which are also generated by `sqlc`.

## Important Variables/Constants

This file itself does not define notable exported package-level constants or variables, other than the types and functions mentioned. The query strings themselves are embedded in the generated `*.sql.go` files.

## Usage Examples

Initializing a `Queries` object (typically done once when the application starts or when a service needing database access is created):

```go
import "github.com/opencode-ai/opencode/internal/db"
// ... assume 'sqlDB' is an initialized *sql.DB connection

// Option 1: Without pre-preparing statements
queries := db.New(sqlDB)

// Option 2: With pre-preparing statements (generally preferred)
// import "context"
// preparedQueries, err := db.Prepare(context.Background(), sqlDB)
// if err != nil {
//     log.Fatalf("Failed to prepare DB queries: %v", err)
// }
// defer preparedQueries.Close() // Important!
```

Using a query method:
```go
// Assuming 'queries' is an initialized *db.Queries object
// import "context"

session, err := queries.GetSessionByID(context.Background(), sessionID)
if err != nil {
    // Handle error
}
// Use session data...
```

Using transactions:
```go
tx, err := sqlDB.BeginTx(context.Background(), nil)
if err != nil {
    // Handle error
}
defer tx.Rollback() // Rollback if not committed

qtx := queries.WithTx(tx) // Use the same 'queries' object or a new one on 'tx'

err = qtx.CreateMessage(context.Background(), db.CreateMessageParams{/* ... */})
if err != nil {
    // Handle error, rollback will occur
    return
}
// ... other operations with qtx ...

if err = tx.Commit(); err != nil {
    // Handle commit error
}
```

## Dependencies and Interactions

- **Internal Dependencies:**
    - Implicitly depends on the SQL query definitions in `*.sql` files within the same directory structure (e.g., `internal/db/sql/`), which `sqlc` uses as input.
    - The methods generated in this file (and the corresponding `*.sql.go` files) are the primary way other parts of the application interact with the database.
- **External Libraries:**
    - `database/sql`: Standard Go library for database interaction.
    - `context`: For managing request-scoped deadlines, cancellation signals, and other values.
- **Interactions:**
    - This file provides the Go API for all database CRUD (Create, Read, Update, Delete) operations defined by the project's SQL queries.
    - It is central to data persistence and retrieval in the application.
    - Services (like `session.Service`, `message.Service`) will use `*db.Queries` to interact with the database.
