# tools.go (in internal/llm/tools)

## Overview

The `tools.go` file, located in the `internal/llm/tools` package, defines the fundamental interfaces, structures, and constants for the tool framework used by the AI agents in OpenCode. It establishes how tools are defined, how they are called, what their responses look like, and how contextual information (like session and message IDs) is passed to them.

## Key Components

### Types and Interfaces
- `ToolInfo (struct)`: Defines the metadata for a tool, which is typically provided to the LLM so it knows how and when to use the tool.
    - `Name (string)`: The unique name of the tool (e.g., "bash", "edit", "glob").
    - `Description (string)`: A detailed natural language description of what the tool does, its parameters, when to use it, limitations, etc. This is a crucial part of the prompt engineering for tool use.
    - `Parameters (map[string]any)`: A map describing the JSON schema of the input parameters the tool expects. The keys are parameter names, and values are maps defining their type and description (conforming to a JSON Schema-like structure).
    - `Required ([]string)`: A list of parameter names that are mandatory for the tool.
- `toolResponseType (string)`: An enum-like type for the type of content in a tool's response.
    - `ToolResponseTypeText ("text")`
    - `ToolResponseTypeImage ("image")` (Currently, only "text" is actively used in constructors).
- `sessionIDContextKey (string)`, `messageIDContextKey (string)`: Custom types for context keys used to pass `sessionID` and `messageID` via `context.Context`.
- `ToolResponse (struct)`: Represents the output from a tool execution.
    - `Type (toolResponseType)`: The type of the content (e.g., "text").
    - `Content (string)`: The actual output content from the tool.
    - `Metadata (string, omitempty)`: Optional JSON string containing additional metadata about the tool's execution (e.g., number of files found, diff statistics).
    - `IsError (bool)`: Flag indicating if the tool execution resulted in an error. If true, `Content` usually contains the error message.
- `ToolCall (struct)`: Represents a request from the LLM to use a specific tool.
    - `ID (string)`: A unique identifier for this specific tool invocation, often generated by the LLM.
    - `Name (string)`: The name of the tool to be called.
    - `Input (string)`: A JSON string containing the parameters for the tool, matching the schema defined in `ToolInfo.Parameters`.
- `BaseTool (interface)`: The fundamental interface that all tools must implement.
    - `Info() ToolInfo`: Returns the `ToolInfo` metadata for the tool.
    - `Run(ctx context.Context, params ToolCall) (ToolResponse, error)`: Executes the tool with the given parameters and context, returning a `ToolResponse` or an error if the tool execution itself fails catastrophically (distinct from `ToolResponse.IsError`).

### Constants
- `ToolResponseTypeText`, `ToolResponseTypeImage`: Define possible tool response types.
- `SessionIDContextKey`, `MessageIDContextKey`: Keys for retrieving session and message IDs from `context.Context`.

### Functions
- `NewTextResponse(content string) ToolResponse`: A constructor for creating a successful `ToolResponse` of type "text".
- `WithResponseMetadata(response ToolResponse, metadata any) ToolResponse`: A helper function to add JSON-marshalled `metadata` to an existing `ToolResponse`. If marshalling fails, it returns the original response.
- `NewTextErrorResponse(content string) ToolResponse`: A constructor for creating an error `ToolResponse` of type "text". Sets `IsError` to `true` and puts the error message in `Content`.
- `GetContextValues(ctx context.Context) (string, string)`: A utility function to extract `sessionID` and `messageID` from a `context.Context` object using the predefined context keys. Returns empty strings if not found.

## Important Variables/Constants
- `SessionIDContextKey` and `MessageIDContextKey`: Standard keys for passing essential contextual IDs to tools.
- The `BaseTool` interface and `ToolInfo`, `ToolCall`, `ToolResponse` structs are the core data structures defining the tool interaction protocol.

## Usage Examples

Defining a new tool:
```go
// mytool.go
package mytools

import (
    "context"
    "github.com/opencode-ai/opencode/internal/llm/tools"
)

type myTool struct {}

func NewMyTool() tools.BaseTool { return &myTool{} }

func (t *myTool) Info() tools.ToolInfo {
    return tools.ToolInfo{
        Name: "my_custom_tool",
        Description: "Does something amazing.",
        Parameters: map[string]any{
            "param1": map[string]any{"type": "string", "description": "First parameter"},
        },
        Required: []string{"param1"},
    }
}

func (t *myTool) Run(ctx context.Context, call tools.ToolCall) (tools.ToolResponse, error) {
    // ... parse call.Input ...
    // ... execute tool logic ...
    // sessionID, messageID := tools.GetContextValues(ctx) // Access context if needed
    return tools.NewTextResponse("Amazing result"), nil
}
```

An LLM agent would receive `ToolInfo` for all available tools. When it decides to use one, it sends a `ToolCall` (typically as part of its own response structure). The agent system then dispatches this `ToolCall` to the appropriate tool's `Run` method.

## Dependencies and Interactions

- **Internal Dependencies:** None beyond standard Go packages for this specific file. However, the types and interfaces defined here are fundamental and used by all other tool implementations (e.g., `bash.go`, `edit.go`) and by the agent logic that invokes tools (`internal/llm/agent/agent.go`).
- **External Libraries:**
    - `encoding/json`: For marshalling metadata in `WithResponseMetadata`.
    - `context`: For passing request-scoped data and cancellation signals.
- **Interactions:**
    - This file establishes the contract for all tools within the OpenCode system.
    - It defines how tools describe themselves to the LLM (`ToolInfo`).
    - It defines how the LLM requests a tool execution (`ToolCall`).
    - It defines how tools report their results or errors (`ToolResponse`).
    - The `GetContextValues` function provides a standardized way for tools to access session-specific and message-specific identifiers if their logic requires it (e.g., for permission checking, history logging).
